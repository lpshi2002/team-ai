Superseded by `DEC-0002`. This record is preserved because the project now explicitly prefers the final source-grounded deliberation-memory structure over an MVP-style "add later" framing.

## Question

Should the repository start with Markdown/YAML records or with a heavier agent framework?

## Decision

Start with Git-managed Markdown/YAML records, hidden internal routing, explicit finance policy, approved decision records, and manual evaluation questions.

## Rationale

- The current repository is small: source PDFs, one meeting note, one project-idea document, and one derived HTML file.
- The team needs durable judgment context before it needs vector infrastructure.
- Markdown/YAML keeps team decisions reviewable in Git and easy for humans to correct.
- Frameworks such as vector databases, MCP, ADK, or multi-agent orchestration should be added after evaluation shows a real need.

## Strongest Countercase

A framework-first build could look more impressive in a hackathon demo and provide traces, tools, or retrieval sooner.

## Why The Decision Holds

The hard part is not tool plumbing yet. The hard part is separating source material, approved team principles, rejected alternatives, current project state, and unreviewed AI memory.

## Reconsider If

- The corpus grows enough that keyword and manifest lookup become unreliable.
- Multiple AI surfaces need shared context access.
- Manual evaluation shows that hidden routing and single-agent multi-pass reasoning are not enough.
